# 使用示例 / Example requests

## 1. 分层架构

```text
使用 logic-render 为这段文字配图：
企业知识助手分为三层。知识层负责文档处理与索引维护；检索层负责片段检索与证据整理；
交互层负责问题理解并生成带引用的回答。知识层支撑检索层，检索层支撑交互层。
权限与评估贯穿三层。用于中文技术文章。
```

预期：分层架构，箭头表示能力支撑，跨层职责单列；具体内容来自输入。

## 2. 定性比较

```text
使用 logic-render，给我一段完整生图提示词，不要生成图片：
对比手工检索、关键词检索、语义检索。
手工检索：启动快，但重复劳动多。
关键词检索：部署简单，但表达变化时易漏检。
语义检索：匹配意图，但需维护向量索引。
```

预期：统一维度的对比矩阵；无虚构评分；仅输出提示词。

## 3. 精确数据图表

```text
使用 logic-render 画一张横向条形图，单位秒，演示数据：
方案 A 120，方案 B 75，方案 C 45。显示每个数值，突出耗时差异。
请使用可验证比例的绘图方式，给出可编辑文件。
```

预期：从零起始；条长比例 120:75:45；显著标注“演示数据”；优先 SVG 或确定性绘图。

## 4. 流程与反馈

```text
使用 logic-render 给文章配一张 4:3 中文图：
先收集问题，再提炼观点，然后核对证据，最后发布内容。
读者反馈回到收集问题阶段，成为下一轮选题输入。
```

预期：四个主要节点及明确反馈回路；不复制模板中的无关说明。

## 5. 缺数据

```text
使用 logic-render 把“新方案更快更准”画成效果对比图。我还没有测试数值。
```

预期：请求必要数据或提供定性图；不凭空添加提升百分比。

## 6. 手机端复杂内容

```text
使用 logic-render 给公众号配图，保留这 22 个节点：
采集、清洗、去重、切分、脱敏、分类、标注、索引、存储、检索、重排、生成、引用、
审核、反馈、修订、归档、权限、监控、告警、评估、回滚。
目前没有提供依赖关系。优先保证手机阅读清晰。
```

预期：总览与局部细节图；分组注明属于组织建议；22 个节点都有去处，避免虚构因果链。

## 7. 指定模板构图

```text
使用 logic-render，沿用 logic-01.png 左上角 G01 反馈驱动闭环的四阶段环形布局，
生成一张 16:9 中文图，保留青蓝、钴蓝、靛蓝的色阶、细线、投影和外围标注。
图中四个阶段为：提出问题、形成假设、验证结果、修订假设。
修订后回到提出问题，开始下一轮。不要把四个模板一起画进成图。
```

预期：遵循明确指定的环形布局，以真实内容替换样例文案；交付一张完整闭环图。

## 8. 参考风格，自由构图

```text
使用 logic-render，参考 layered-02.png 右下角 L08 的视觉风格，
画一张 16:9 中文技术图：检索服务、分析服务、通知服务地位平等，
都向事件总线发布事件，也从总线订阅事件。三个服务之间没有直接调用关系。
按这些关系自行设计布局，保持模板的色阶、精细轮廓、半透明材质和柔和阴影。
```

预期：以总线与同级服务表达发布、订阅关系；自由设计网络构图，保留参考图的视觉品质。
原生生图与代码绘图均按实际关系组织结构，模板编号不要求沿用四层平台。
