# Layered architecture

Open [sheet 01](../assets/layered-01.png) and [sheet 02](../assets/layered-02.png).
Each sheet contains four complete compositions in a 2×2 grid. Read left to
right, top to bottom. Sheet 01 contains 01–04; sheet 02 contains 05–08.

| ID | Panel | Appropriate relationship |
| --- | --- | --- |
| L01 | 多层能力支撑 | Capabilities supported by resources across responsibility layers |
| L02 | 信息收敛与分发 | Multiple inputs transformed and distributed into different outputs |
| L03 | 共享平台与场景 | Peer scenarios supported by shared business and data capabilities |
| L04 | 分层治理架构 | Nested responsibility levels with cross-cutting governance |
| L05 | 战略分层与执行 | Goals supported by capabilities and concrete actions |
| L06 | 双体系协同 | Distinct systems that exchange information and share standards |
| L07 | 能力演进路径 | Ordered development stages with increasing capability |
| L08 | 模块化服务底座 | Services and resources in an explicitly layered platform |

Borrow thin translucent planes, fine contour lines, layered shadows, dotted
guides and precise annotations. Derive the number, shape and arrangement of
modules from the source. Stack layers when the content has a hierarchy; peer
services or branches can use a network or flow layout with the same visual
treatment. Keep a panel's specific arrangement only when explicitly requested.
Retain clear primary structure and relevant supporting detail. Distinguish
support direction from execution order. Orbital placement groups peers; it does
not establish causation. Governance rails require source-supported responsibilities.

Funnel, pyramid and platform sizes are conceptual. If geometry must encode
quantities, use exact data-driven charts. Template content is an example, not a
claim about the user's product.
